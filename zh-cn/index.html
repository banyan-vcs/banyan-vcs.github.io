为什么是 banyan

git 赢了，大仓托管仍是短板。

五个观察决定了设计，两个结构性答案随之而来。

git 是绕不开的行业标准

二十年深耕，从个人项目到最大的企业。任何可信的方案都不能要求任何人离开 git。

大仓托管是 git 的短板

Android 级 monorepo 撞上它的极限：几十 GB、数百万对象、小时级 clone。浅化/稀疏/部分克隆治标不治本。

monorepo 是代码维护的去向

现代构建系统上，源码依赖是让代码保持存活的最优方式：跨包原子变更、零发布延迟、一次提交协调多方。

目录级权限成为结构性需求

部门边界、合规隔离、供应商可见性——原生 git 无法表达；按目录拆仓则摧毁了 monorepo 本来要提供的东西。

AI Agent 放大冲突频率

协作频率从人类的天级走向 agent 的分钟级，中心化 ref 的瓶颈被放大：推送锁、全量协商、force-push 与 rebase 级联。

分布式是构造性的

pack CAS 分片 + 小体量元数据面：存储横向扩展、不绑定单机。代码——企业的核心资产——获得数据库级的可靠性，而不是一块单盘的可靠性。

目录锚定时间线

每个目录拥有自己的提交历史。任何子树都是仓库、传输 O(子目录)、目录之间零锁竞争——权限边界就是时间线边界。原生能力，而非外挂。

远景：代码存储成为独立的基础设施层——任何平台、任何客户端、任何规模。

今天就能用的

服务端做得不一样的八件事

⑂任何子树都是仓库

/r/demo.git/tree/plumbing 是一等公民的 clone URL。目录时间线构造性地小；跨目录推送零竞争，根视图读取时织入。

⇄协议完备的 git 边界

Smart HTTP v0/v1/v2 与 git-over-SSH。原生 git CLI 零插件可用——含 partial clone、浅化、thin pack、过滤抓取。64 个集成用例以真 git 钉住。

▤有界内存服务

clone 形态的抓取全部流式化：精确命中整包直传，未命中走无 delta 流式编码器——闭包永不驻留。72MiB 三 pack 仓在 64MiB 软限制下 clone，峰值 12.3MiB。

⇉收敛列车

同目录推送在时间线队列串行、服务端收敛（纯 Go merge-ort 子集）。8 个并发写者耗时 0.52× git——没有 rebase 循环。

⬢构造性 HA

refs 服务 + 散布 pack 存储（R 副本）+ 无状态网关。杀掉一个存储节点，读写照常，reconciler 自动补副本——全链路实测。

⚿治理内建

仓库/目录/分支三粒度授权、个人分支可见性、全 clone 尺寸预算、receive hooks，以及全角色运维面（pprof + 服务路径计数器）。

☘需要时用薄 CLI

可选的 .banyan 工作区只下载检出所需——无本地历史，status 保持在线级速度。真 git 始终是兼容边界与全量后门。

▦存储行为可控

几何 repack 永不重打大包、idx v2 64 位偏移、流式摄入扛住数百 GB 导入、命名/哈希双寻址支持在线改名。

快速开始

一条命令跑起来

Docker 单节点

docker compose up -d
# web  http://localhost:8101 (alice/bob/admin，密码 demo)
# git  http://alice:demo@localhost:8100/r/demo.git

git clone http://alice:demo@localhost:8100/r/demo.git
# 任何子树同样是仓库：
git clone http://alice:demo@localhost:8100/r/demo.git/tree/plumbing

HA 集群 demo

# refs 服务 + 4 存储节点 + 无状态网关，
# pack 以 3 副本散布；杀一个节点，继续服务
docker compose -f docker-compose.cluster.yml up -d

# 或跟随完整走查脚本：
bash demo/cluster-demo.sh

源码构建

go build ./... && go vet ./...

go run ./cmd/banyand \
  -listen 127.0.0.1:8097 \
  -root ./banyand-data -meta sqlite

git remote add banyan http://127.0.0.1:8097/r/myrepo.git
git push banyan main   # 首推自动建仓
