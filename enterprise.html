One tree, two licenses, a bright line

The storage layer banyan exists for — protocol, timelines, HA, performance — is and stays open. Enterprise capabilities live in the same tree, in a physically separate enterprise/ directory, under its own license. The boundary is the directory: easy to see, easy to trust.

Open core

MIT

Everything a code-storage layer needs:

  • The full git protocol boundary — HTTP v0/v1/v2 and SSH
  • Directory-anchored timelines and the weaving engine
  • Sharded pack storage, streaming ingest and serving
  • The HA line: replicas, reconciler, node failure and recovery
  • Token auth, branch visibility, hooks, the ops plane
  • CLI, web console, benchmark harness, all 64 integration cases

enterprise/

Enterprise license

The licensing plane ships today (plan-gated features, offline license tokens, a keygen tool); feature areas land incrementally:

  • Audit — storage-plane visibility: bare-OID fetches, wire-level actions the platform cannot see
  • Identity & policy — SSO, directory-backed dynamic policy sources, token lifecycle
  • Disaster recovery — cross-cluster replication, zone-aware placement, backup orchestration
  • Governance — compliance deletion, object-level GC
  • Multi-tenancy — organizations, quotas, rate limits

Free for development and testing; production use requires a subscription. No change-date conversion — the split is permanent and visible in the tree.

LICENSE.enterprise

The red line

Features the roadmap has promised in the open — HA basics, personal token auth, branch visibility, protocol and performance work — stay open regardless of how the enterprise set grows. If it is on the open roadmap, it does not move behind the line.
